# PRD: Z-Gallery — Deterministic Generative Art System

> Generated by /prd on Feb 15, 2026
> Upgraded: Feb 15, 2026 — from gallery site to collectible art system

## Problem & Context

Z-Gallery exists as a functional prototype — it renders generative art, but it doesn't create value. Visitors see pretty pictures and leave. There's no reason to return, nothing to collect, no consequence to creating, and no distribution strategy. The ZEngine is a genuine technological differentiator (deterministic, seed-signed, infinite outputs), but the current site treats it like a demo instead of a system. The upgrade transforms Z-Gallery from a portfolio website into a deterministic generative art system where every artwork is a limited, seed-signed artifact that can be collected, remixed, and evolved.

## Positioning

> Z-Gallery is a deterministic generative art system where every artwork is a limited, seed-signed artifact that can be collected, remixed, and evolved.

Not a gallery. Not a demo. A **system**. This framing:
- Attracts collectors (scarcity + ownership)
- Impresses developers (deterministic rendering + open parameters)
- Signals depth to investors (system, not site)
- Creates a category (deterministic collectible art, no blockchain required)

## Users

**Primary user:** Art collectors & enthusiasts — people who appreciate visual art, want something unique for their wall, and respond to scarcity. They browse, discover, collect seeds, and request prints.

**Secondary user:** Creative technologists — developers and designers who want to understand the generative process, remix existing works, play with the engine, and share their creations. They tinker, fork, and evangelize.

**Tertiary user:** Potential collaborators & buyers — investors, gallery owners, brands, or curators who discover the site and want to reach out. They need to be impressed quickly and have a clear path to contact.

## Core Features (v1)

1. **Collectible Art System** — Every artwork has edition limits, a signed seed hash, generation timestamp, and a mint counter ("3 of 30 claimed"). Scarcity without blockchain. Tinkering in the playground has consequence — beautiful creations can be claimed.

2. **Interactive Studio with Claiming** — Visitors tweak archetype, palette, seed, and density in real-time. When they create something they love, they can "Claim this seed" (limited to 10 prints per playground creation). Claiming requires email — this feeds the collection and the mailing list simultaneously.

3. **Smart Gallery Curation** — Browse all 31 canonical works with rich filtering by era, archetype, palette. Cards show live SVG rendering, title, edition status, and key metadata. Smooth transitions between views.

4. **Remix & Lineage** — Every artwork shows its remix history: Original → Remix 1 → Remix 2. Users can "Remix this artwork" (fork with modified parameters). Remix lineage creates viral loops — people share because they modified something. Art becomes evolutionary.

5. **My Collection** — Users save seeds to a personal collection (LocalStorage + email backup). Optional public profile link. This creates identity, investment, and return visits. The hook model: Trigger → Action → Reward → Investment.

6. **Manifesto & Philosophy** — A short, poetic manifesto explaining why deterministic art matters, why seeds are signatures, and why constraint creates value. This turns the site from technical to cultural — collectors buy meaning, not pixels.

7. **Contact & Inquiry Flow** — Simple way for visitors to express interest: request a print, inquire about commissions, or start a conversation. Not a full checkout — inquiry-based with social proof ("12 collectors interested in this work").

- Same seed, same artwork, forever — unlike AI art, nothing is hallucinated
- The artist designs the system; the system designs the art

- The constraint is the art

## User Flows

### Flow 1: Collector Journey
1. User lands on homepage — sees hero with live-rendered featured artwork
2. Reads the manifesto — understands this is a system, not a gallery
3. Sees the featured limited drop — "Edition 7 of 30 — 23 remaining"
4. Clicks "Explore Gallery" — lands on filterable gallery grid
5. Filters by era or archetype — grid updates smoothly
6. Clicks an artwork — sees full detail page with rendering + metadata + edition status
7. Clicks "Request Print" — enters email, selects size preference
8. Discovers related works and remix lineage — continues exploring
9. Saves favorites to "My Collection" (requires email if first time)

### Flow 2: Creator / Tinkerer Journey
1. User lands on homepage — sees "Create in the Studio" CTA
2. Clicks into Interactive Studio
3. Selects archetype, palette, adjusts density slider
4. Watches the SVG regenerate in real-time
5. Finds a combination they love
6. Clicks "Claim this seed" — enters email, seed is saved to their collection
7. Gets a shareable link with their creation
8. Sees "Limited to 10 prints" — creation has consequence

### Flow 3: Remixer Journey
1. User arrives at an artwork (via share link or gallery)
2. Sees the remix lineage: "Original → 3 remixes"
3. Clicks "Remix this artwork" — opens studio with parent's parameters pre-loaded
4. Modifies parameters — creates a derivative
5. Claims the remix — it shows lineage back to the original
6. Shares the remix — friends see the chain and want to create their own

### Flow 4: Collaborator / Buyer Journey
1. User lands on homepage — impressed by art quality and system concept
2. Reads manifesto + theory — understands the technology and philosophy
3. Sees social proof: "142 seeds claimed this month"
4. Clicks "Get in Touch" — fills out contact form
5. Conversation starts

## Scarcity Model

### Canonical Works (31 in catalog)
- **Edition size:** 30 prints per work
- **Signed seed hash:** Deterministic hash of (archetype + palette + seed + density)
- **Generation timestamp:** When the work was first cataloged
- **Mint counter:** "Claimed: 0 / 30" (tracks interest/requests)
- **Status:** Available / Limited / Sold Out

### Playground Creations (user-generated)
- **Edition size:** 10 prints per claimed seed
- **Claim requires:** Email address
- **Remix lineage:** Array of parent seed IDs
- **Creator attribution:** Email (hashed for privacy) + timestamp

### Data Structure (extends z-catalog.js)
```javascript
// New fields per artwork
{
  editionSize: 30,           // Max prints
  claimed: 0,                // Current claims
  seedHash: 'a3f2b1...',    // Deterministic hash
  createdAt: '2018-01-15',  // First cataloged
  status: 'available',       // available | limited | claimed
  remixOf: null,             // Parent seed ID (null for originals)
  remixes: [],               // Array of child seed IDs
}
```

### Storage (no backend required)
- **Canonical editions:** JSON file (`data/editions.json`) — static, updated manually
- **User collections:** LocalStorage (`z-gallery-collection`)
- **Claims/interest:** Netlify Forms (email + seed + size preference)
- **Remix mapping:** JSON file (`data/remixes.json`) — static, updated as remixes are claimed

## Hook Model

| Stage | Mechanism |
|-------|-----------|
| **Trigger** | Share link, social post, remix notification, "new drop" email |
| **Action** | Browse gallery, tinker in studio, remix an artwork |
| **Reward** | Beautiful creation, claimed seed, public collection, remix lineage |
| **Investment** | Saved collection, email subscription, public profile, remix history |

**Key design decisions:**
- Saving a seed requires email — this is the investment gate
- Collections persist in LocalStorage (instant) + email backup (durable)
- Public profile link is optional — low friction for privacy-conscious users
- Remix lineage is always visible — creates social proof and viral spread

## Non-Goals (v1 Scope Firewall)

Explicitly NOT building in v1:
- No payment processing or checkout (inquiry-based only)
- No user accounts or authentication (email-only identity)
- No blockchain, NFTs, or crypto integration (scarcity via system, not ledger)
- No native mobile app (responsive web only)
- No custom commission requests (v2)
- No shopping cart or pricing display on artwork pages (inquiry-based)
- No CMS backend (catalog stays in z-catalog.js, editions in JSON)
- No analytics dashboard (may add PostHog later via /iterate)
- No real-time collaboration or multiplayer features
- No AI-generated art or prompt-based creation (deterministic only)
- No backend server or database (everything client-side + static JSON + Netlify Forms)

## Tech Stack

| Layer | Choice | Rationale |
|-------|--------|-----------|
| Frontend | Vanilla HTML/CSS/JS | Existing stack, no build step, fast, simple. No framework complexity needed. |
| Rendering | ZEngine (z-engine.js) | Existing deterministic SVG engine. Core technology, DO NOT CHANGE. |
| Catalog | z-catalog.js | Existing 31-work catalog with metadata. Extend with edition/remix fields. |
| Edition Data | Static JSON files | `data/editions.json` + `data/remixes.json` — no backend needed. |
| User Collections | LocalStorage | Instant persistence, no auth required. Email backup for durability. |
| Design System | Z-Signal Bauhaus (modernized) | Keep the DNA, refine the execution. More whitespace, contemporary layout. |
| Email Capture | Netlify Forms | Claims, print requests, contact inquiries. Free tier, no backend. |
| Deployment | Netlify | Static site, free tier, instant deploys, global CDN, built-in forms. |
| Seed Hashing | Simple JS hash | Deterministic hash of parameters for seed signing. Client-side. |
| URL Encoding | Query params | Shareable configurations: `?archetype=X&palette=Y&seed=Z&density=D` |
| OG Images | SVG → Canvas → PNG | Generate shareable preview images from live SVG renders. |
